เมื่อมีข้อมูลสะสมพอ ระบบจะเปิดความสามารถอีกชุดให้เอง:

ถามน้อง Orderถามข้อมูลเป็นภาษาไทยธรรมดา ได้คำตอบพร้อมกราฟ
พยากรณ์คาดการณ์ว่าเดือนหน้าต้องเตรียมวัตถุดิบ เครื่องจักร และแรงงานเท่าไหร่
สุขภาพการผลิตเฝ้าดู Yield ส่วนเกินจากแผน ปริมาณงาน และจังหวะการผลิตรายสัปดาห์
MFG / EXPเก็บวันผลิต–วันหมดอายุของแต่ละ batch พร้อมตรวจ Shelf Life ให้อัตโนมัติ
ขอบเขตการสแกน: ระบบอ่านเฉพาะคอลัมน์ "ลำดับ" ถึง "หน่วย" (ฝั่งซ้ายของเส้นปะ) — ข้อมูลหลังเส้นปะจะถูกข้ามทั้งหมด
ตามค่าเริ่มต้นระบบจะส่งภาพทั้งหน้าให้ AI อ่าน ไม่ตัดภาพ เพื่อไม่ให้คอลัมน์ขวาหายไปโดยไม่มีใครรู้ — Admin เปิดโหมดตัดภาพที่เส้นปะได้ที่หน้าตั้งค่าหากต้องการประหยัดค่า AI (ดูข้อ 13.4)

2. บทบาทผู้ใช้งาน (Roles)

บทบาทสิทธิ์การใช้งาน
Super Admin เห็นข้อมูลทุกโรงงาน จัดการโรงงาน กำหนดสังกัด และใช้งานได้ทุกฟีเจอร์เหมือน Admin
Admin ใช้งานได้ทุกฟีเจอร์ — สแกน, อนุมัติ, จัดการผู้ใช้, ตั้งค่า AI, Export, ดูประวัติ, ปรับ Permission Matrix, ล้างข้อมูลเพื่อเริ่มระบบใหม่
Reviewer ตรวจสอบ/แก้ไขฉบับร่างหรือรายการที่ Staff ส่งมา แล้วส่งต่อไปอนุมัติ, แก้ไขรายการที่ถูกตีกลับ, ดูประวัติการใช้งาน, Export Excel
Approver อนุมัติรายการขั้นสุดท้าย หรือตีกลับให้ Reviewer พร้อมเหตุผล, ดูประวัติการใช้งาน, Export ส่ง SAP
Staff สแกน/อัปโหลดเอกสารเข้าคิว, ตรวจสอบฉบับร่างแล้วกด “ส่งตรวจสอบ”, ดูรายการ, Export Excel

Admin ปรับสิทธิ์แต่ละ Role ได้ที่หน้า "ผู้ใช้งาน" → Permission Matrix

สังกัดโรงงาน: ผู้ใช้ทุกคน (ยกเว้น Super Admin) ต้องมีสังกัดโรงงาน จึงจะอัปโหลดและดูข้อมูลได้ — ข้อมูลจะถูกแยกตามโรงงาน ผู้ใช้จะเห็นเฉพาะข้อมูลของโรงงานตัวเอง
Super Admin กำหนดสังกัดให้ผู้ใช้ได้ที่หน้า "ผู้ใช้งาน" โดยกดเลือกโรงงานในคอลัมน์สังกัด
หน้า ถามน้อง Order, พยากรณ์ และ สุขภาพการผลิต เปิดให้ทุกบทบาทใช้ได้ เพราะเป็นการดูข้อมูลอย่างเดียว ไม่มีการแก้ไขใด ๆ

3. เมนูและการใช้งานบนมือถือ

เมนูด้านซ้ายแบ่งเป็น 3 กลุ่มตามลักษณะงาน:

กลุ่มใช้ทำอะไร

วิเคราะห์และรายงานถามน้อง Order · พยากรณ์ · สุขภาพการผลิต · Export — ดูภาพรวมและตัดสินใจ

เมนูที่บทบาทของคุณไม่มีสิทธิ์จะถูกซ่อน หากทั้งกลุ่มถูกซ่อน หัวข้อกลุ่มจะหายไปด้วย

3.1 ย่อ/ขยายเมนู

กดปุ่ม ‹ ที่มุมขวาบนของเมนู เพื่อย่อเมนูให้เหลือเฉพาะไอคอน ได้พื้นที่ทำงานกว้างขึ้น — ชี้ที่ไอคอนเพื่อดูชื่อเมนู กดปุ่มเดิมอีกครั้งเพื่อขยายกลับ

ระบบจำค่าที่คุณเลือกไว้ในเครื่องนั้น ๆ เปิดครั้งหน้าจะอยู่ในสถานะเดิม

5. การสแกนเอกสาร

5.4 เมื่อสแกนล้มเหลว

ระบบจะแสดงเหตุผลเป็นภาษาไทยที่อ่านเข้าใจได้ ไม่ใช่ข้อความ error ทางเทคนิค เช่น

  • "ยังไม่ได้ตั้งค่า API Key — กรุณาตั้งค่าในหน้า Settings"
  • "AI ถูกเรียกถี่เกินไป — กรุณารอสักครู่แล้วลองใหม่"

ไฟล์ที่ล้มเหลวซ้ำหลายครั้งจะถูกย้ายไปรายการ "สแกนล้มเหลว" ซึ่ง Admin สั่งลองใหม่หรือลบทิ้งได้

5.5 สแกนอัตโนมัติ

ระบบสแกนคิวอัตโนมัติทุก 5 นาที — ไฟล์ที่อัปโหลดหรือดึงจาก Google Drive จะถูกประมวลผลโดยอัตโนมัติ

6. รายการ แก้ไข และ MFG/EXP

6.1 ค้นหาและกรอง

หน้า "รายการ" แสดง Production Order เรียงจากใหม่สุด มีตัวกรอง 4 แบบใช้ร่วมกันได้:

ค้นหาพิมพ์เลขที่ ชื่อสินค้า หรืออีเมลผู้อนุมัติ
สถานะทั้งหมด / รออนุมัติ / ต้องตรวจสอบ / Draft / อนุมัติแล้ว
ช่วงวันที่ตั้งแต่วันที่ – ถึงวันที่ (อ้างอิงวันที่บนเอกสาร)
ปุ่มลัด7 วัน · 30 วัน · เดือนนี้ · เดือนที่แล้ว · ทั้งหมด
เมื่อใช้ตัวกรองวันที่หรือคำค้น ระบบจะโหลดรายการทั้งหมดให้ครบก่อนกรองโดยอัตโนมัติ เพราะการกรองจากรายการที่โหลดมาเพียงบางส่วนจะให้ผลลัพธ์ที่ไม่ครบและทำให้เข้าใจผิด

6.2 แก้ไขรายการ

กดปุ่ม แก้ไข ที่รายการนั้น → หน้าต่างแก้ไขแสดง:

  • ส่วนหัว — Production Order, วันที่, Item No., ชื่อผลิตภัณฑ์, คลังรับเข้า
  • ยอดผลิต Plan และหน่วยผลิต
  • ตารางรายการ — ลำดับ, รหัส, รายการวัตถุดิบ, Type, Qty, Plan, คลัง, หน่วย
  • MFG / EXP Date — ตาราง batch วันผลิต–วันหมดอายุ (ดูข้อ 6.5)
  • ภาพต้นฉบับ — กดดูภาพที่สแกนเข้ามา (ขยาย/ย่อได้)

แก้ไขค่าใดก็ได้ สามารถ + เพิ่มแถว หรือ ลบแถว ได้

ยอดผลิตจริงไม่มีช่องกรอกในส่วนหัวแล้ว เพราะยอดที่รับเข้าจริงถูกบันทึกเป็นราย batch ในตาราง MFG/EXP (คอลัมน์ Receive Qty.) ซึ่งละเอียดกว่าและตรงกับเอกสารมากกว่า

6.3 บันทึกฉบับร่าง (Draft)

  • บันทึกทุกการเปลี่ยนแปลงรวมถึงการ Tick ยืนยันค่าต่าง
  • สถานะเปลี่ยนเป็น ฉบับร่าง
  • กลับมาแก้ไขเพิ่มเติมได้ภายหลัง

6.4 นำทางระหว่างรายการ

ใช้ปุ่ม ◀ / ▶ มุมขวาบนของหน้าต่างแก้ไข เพื่อข้ามไปรายการก่อนหน้า/ถัดไปโดยไม่ต้องปิดหน้าต่าง

6.5 MFG / EXP Date (วันผลิต–วันหมดอายุ)

ถ้าใบสั่งผลิตมีตาราง batch วันผลิต–วันหมดอายุ ระบบจะอ่านเข้ามาให้เอง และแสดงเป็นส่วน MFG / EXP Date ในหน้าต่างแก้ไข หนึ่งแถวต่อหนึ่ง batch

คอลัมน์ความหมาย
Order No.เลขใบสั่งผลิต — ดึงมาจากส่วนหัวให้อัตโนมัติ
Item No.รหัสผลิตภัณฑ์ — ดึงมาจากส่วนหัวให้อัตโนมัติ
MFG Dateวันที่ผลิตของ batch นั้น
EXP Dateวันหมดอายุของ batch นั้น
Shelf Lifeจำนวนวันระหว่าง MFG ถึง EXP — ระบบคำนวณให้ทันทีที่แก้วันที่
Receive Qty.ยอดที่รับเข้าจริงของ batch นั้น
หน่วยหน่วยนับ เช่น ชิ้น

ในไฟล์ Excel จะมีคอลัมน์ คลัง ต่อท้ายอีกหนึ่งคอลัมน์ — ดึงจากช่อง "คลังรับเข้า" ในส่วนหัว (ช่อง Whse ของแถวผลิตภัณฑ์บนฟอร์ม เช่น DW-1001) ฟอร์มรุ่นเก่าที่ยังไม่มีช่องนี้จะขึ้นเป็น n/a และกรอกเพิ่มเองได้ที่ส่วนหัวของหน้าต่างแก้ไข

กด + เพิ่ม batch เพื่อเพิ่มแถว หรือกด × ท้ายแถวเพื่อลบ — บันทึกแล้วข้อมูลจะเข้าไปอยู่ในไฟล์ Excel แผ่นที่สอง

6.6 การตรวจ Shelf Life

ตัวเลข Shelf Life เปลี่ยนสีตามผลการตรวจ เพื่อจับวันที่ที่อ่านมาผิดก่อนข้อมูลจะหลุดเข้า SAP:

0–7 วันปกติ บันทึกได้เลย
เกิน 7 วันผิดปกติ — ระบบถามยืนยันก่อนบันทึกหรืออนุมัติ
ติดลบ ⚠️EXP อยู่ก่อน MFG ซึ่งเป็นไปไม่ได้ — บันทึกและอนุมัติไม่ได้จนกว่าจะแก้
AI ไม่ได้เป็นคนแปลงวันที่ — มันส่งเฉพาะตัวเลขตามที่เขียนในช่อง (เช่น "110826") แล้วระบบแปลงเป็นวันที่เองแบบ DDMMYY เพราะลำดับวัน/เดือน เป็นรูปแบบตายตัวของฟอร์ม ไม่ใช่สิ่งที่ต้องเดา
ตอนที่ปล่อยให้ AI แปลงเอง มันเคย "แก้ให้ดูสมเหตุสมผล" จนได้วันหมดอายุมาก่อนวันผลิต ตอนนี้ตัวเลขที่อ่านไม่ครบหรือเป็นวันที่ที่ไม่มีจริงจะถูกปล่อยว่างไว้ ไม่เดาให้
Shelf Life ติดลบ = บันทึกไม่ได้เลย ระบบจะขึ้นกล่องแจ้งเตือน ไฮไลต์แถวนั้นเป็นสีแดง และพาไปที่ช่องวันที่ให้แก้ทันที ไม่มีปุ่มให้กดผ่าน เพราะวันหมดอายุที่มาก่อนวันผลิต ไม่มีทางตรงกับเอกสารได้ จึงไม่ใช่เรื่องที่ต้องให้ใครยืนยัน
ส่วนกรณี เกิน 7 วัน ยังเป็นกล่องให้ยืนยัน — กด ยกเลิก เพื่อกลับไปแก้ หรือ ตกลง หากตรวจกับเอกสารแล้วว่าถูกจริง

บางรายการจะมีป้ายเตือน ต้องตรวจสอบ ซึ่งเกิดจาก AI อ่านข้อมูลได้ไม่ครบหรือพบความขัดแย้ง:

สาเหตุความหมาย

ไม่พบยอดผลิตจริงAI อ่านตัวเลข Actual Total ไม่ได้
ไม่พบคอลัมน์ปริมาณที่ต้องใช้ทั้งใบทุกแถวไม่มีค่า Plan — อาจถ่ายไม่ครบหน้า

8.1 ไฟล์ Excel มี 2 แผ่น

แผ่นงานเนื้อหา
production_order หนึ่งแถวต่อหนึ่งรายการวัตถุดิบ — Production Order · วันที่ · Item No. · ผลิตภัณฑ์ · หน่วยผลิต · ลำดับ · รหัส · รายการวัตถุดิบ · Type · Issue Qty · คลังสินค้า · Plan · หน่วย
MFG_EXP หนึ่งแถวต่อหนึ่ง batch — Production Order · วันที่เอกสาร · Item No. · ผลิตภัณฑ์ · MFG Date · EXP Date · Receive Qty. · หน่วย · คลัง

แผ่น MFG_EXP จะถูกสร้างเฉพาะเมื่อมีใบที่บันทึกข้อมูล batch ไว้ — ถ้าไม่มีเลย ไฟล์จะมีแผ่นเดียวตามปกติ

คอลัมน์ Issue Qty คือปริมาณที่เบิกจริงตามใบ ส่วน Receive Qty. ในแผ่น MFG_EXP คือยอดที่รับเข้าจริงของแต่ละ batch — ทั้งสองแผ่นเชื่อมกันด้วยเลข Production Order

8.2 การติดตามการส่งเข้า SAP

ระบบจดจำว่าใบไหนเคยอยู่ในไฟล์ Export แล้ว เพื่อไม่ให้มีใบตกหล่นจากการคีย์เข้า SAP

  • ด้านบนหน้า Export มีแถบบอก "ยังไม่ได้ส่งเข้า SAP กี่ใบ" พร้อมวันที่ของใบที่ค้างนานที่สุด
  • ปุ่ม "Export เฉพาะที่ยังไม่ได้ส่ง" — กดครั้งเดียวได้ครบทุกใบที่ค้าง ไม่ต้องเลือกวันที่เอง
  • ในหน้ารายการ ใบที่ส่งแล้วจะมีป้าย SAP ✓ ส่วนใบที่อนุมัติแล้วแต่ยังไม่ส่งจะขึ้น รอส่ง SAP
  • ตัวกรอง "อนุมัติแล้ว · ยังไม่ส่ง SAP" ในหน้ารายการ ใช้ดูรายการที่ค้างทั้งหมด
  • ประวัติการส่งเข้า SAP ด้านล่างหน้า Export บันทึกทุกครั้งที่ Export — เวลา ผู้ทำ จำนวนใบ และเงื่อนไขที่ใช้
Export ซ้ำได้เสมอ ระบบไม่บล็อก เผื่อไฟล์หายหรือต้องส่งให้คนอื่นอีกรอบ — การ Export ซ้ำไม่เปลี่ยนสถานะของใบที่ส่งไปแล้ว และไม่ทำให้ตัวเลข "ยังไม่ได้ส่ง" ผิด
หากกด Export แล้วไฟล์ไม่ได้ดาวน์โหลดจริง (เช่น เน็ตหลุด) ให้ Admin กด "ยกเลิกการทำเครื่องหมาย" ที่แถวนั้นในประวัติ ใบเหล่านั้นจะกลับมานับรวมใน "ยังไม่ได้ส่งเข้า SAP" อีกครั้ง
เฉพาะใบที่ อนุมัติแล้ว เท่านั้นที่ถูกทำเครื่องหมาย — ใบที่ยังไม่อนุมัติที่หลุดเข้าไฟล์จะไม่ถูกนับว่าส่งแล้ว

9. ถามน้อง Order (AI)

น้อง Order คือผู้ช่วยที่ตอบคำถามเกี่ยวกับข้อมูลการผลิตเป็นภาษาไทยธรรมดา พิมพ์ถามได้เลย ไม่ต้องเรียนรู้คำสั่ง

9.1 ถามอะไรได้บ้าง

ประเภทตัวอย่างคำถาม
ยอดรวม"เดือนที่แล้วใช้แป้งสาลีไปเท่าไหร่"
จัดอันดับ"วัตถุดิบ 10 อันดับที่ใช้เยอะที่สุดในไตรมาสนี้"
เปรียบเทียบ"เทียบการใช้น้ำตาลทรายเดือนนี้กับเดือนที่แล้ว"
แนวโน้ม"แนวโน้มการใช้มายองเนส 6 เดือนที่ผ่านมา"
ผลต่างจากแผน"รายการไหนเบิกเกินแผนมากที่สุด"
การเตรียมของ"เดือนหน้าต้องเตรียมวัตถุดิบอะไรบ้าง"

9.2 คำตอบแสดงเป็นภาพ

  • กราฟแนวโน้ม — เมื่อถามข้อมูลหลายเดือน พร้อมค่าสูงสุด ต่ำสุด เฉลี่ย และการเปลี่ยนแปลงตลอดช่วง
  • แถบจัดอันดับ — เมื่อเปรียบเทียบหลายรายการ
  • ตัวเลขใหญ่ — เมื่อคำตอบมีค่าเดียว
  • การ์ดเปรียบเทียบ — เมื่อเทียบสองช่วงเวลา

กด "ดูตัวเลขทั้งหมดเป็นตาราง" ใต้กราฟ เพื่อดูตัวเลขดิบทุกแถว

9.3 ทำไมตัวเลขถึงเชื่อถือได้

AI ทำหน้าที่เพียง แปลคำถามเป็นเงื่อนไขค้นหา และ เรียบเรียงคำตอบเป็นประโยค เท่านั้น ส่วนการคำนวณตัวเลขทั้งหมดทำโดยโปรแกรมจากฐานข้อมูลจริง
เหตุผลคือ AI ที่ทั้งอ่านข้อมูลและบวกเลขเองจะตอบตัวเลขผิดเป็นครั้งคราวอย่างมั่นใจ และยอดวัตถุดิบที่ผิดจะดูไม่ต่างจากยอดที่ถูกเลยสำหรับคนอ่าน
กด "วิธีที่ระบบตีความคำถาม" ใต้คำตอบ เพื่อตรวจสอบเงื่อนไขที่ระบบใช้ค้นจริง

9.4 การเทียบเดือนที่ยังไม่จบ

ถ้าถามเทียบ "เดือนนี้" กับ "เดือนที่แล้ว" ในขณะที่เดือนนี้ยังไม่จบ ระบบจะเทียบเป็นค่าเฉลี่ยต่อวันแทนยอดรวม พร้อมขึ้นกล่องเตือนสีเหลือง เพราะการเทียบยอดรวมของ 4 วันกับ 30 วันจะทำให้ดูเหมือนยอดดิ่งลงทั้งที่ไม่มีอะไรเปลี่ยน

10. พยากรณ์ความต้องการวัตถุดิบ

คาดการณ์ว่าช่วงถัดไปต้องเตรียมอะไรเท่าไหร่ — เลือกช่วงได้ตั้งแต่ 1 ถึง 6 เดือน

10.1 วิธีคำนวณ

ระบบไม่ได้ทำนายจากยอดใช้ในอดีตโดยตรง แต่ถอด สูตรการใช้ต่อหน่วยผลิต ของแต่ละสินค้าจากใบเบิกจริง แล้วคูณกับยอดผลิตที่พยากรณ์ไว้ของสินค้านั้น
เหตุผล: การใช้วัตถุดิบในโรงงานขึ้นกับว่าจะผลิตอะไรเท่าไหร่ ไม่ใช่ขึ้นกับปฏิทิน ผลลัพธ์จึงขยับตามสัดส่วนสินค้าที่จะผลิตจริง
สูตรใช้ค่ามัธยฐาน จึงไม่เพี้ยนเพราะใบเดียวที่คีย์ผิด

10.2 ตัวกรอง

  • ค้นหา ชื่อวัตถุดิบหรือรหัส
  • ความเชื่อมั่น เชื่อมั่นสูง / ปานกลาง / ผันผวน
  • ใช้ในผลิตภัณฑ์ — เลือกสินค้า แล้วดูว่าวัตถุดิบแต่ละตัวถูกใช้กับสินค้านั้นเท่าไหร่
ปุ่มลัดกรองอะไร และใช้ตอนไหน
ทั้งหมดทุกรายการที่ระบบพยากรณ์ให้
เฉพาะวัตถุดิบเฉพาะของที่ต้องสั่งซื้อและเก็บในคลัง (Type = Item) — ใช้ตอนทำใบสั่งซื้อ
เครื่องจักร/แรงงานเฉพาะ Type = Resource หน่วยชั่วโมง — ใช้ตอนจัดกะและวางรอบเดินเครื่อง
เพิ่มขึ้นจากปกติรายการที่จะใช้มากกว่าค่าเฉลี่ยเดิมเกิน 10% — ต้องเตรียมของเพิ่ม
ผันผวน (ต้องระวัง)รายการที่ความเชื่อมั่นอยู่ระดับ ผันผวน — ห้ามสั่งตามตัวเลขกลางตรง ๆ

10.3 "ผันผวน" หมายถึงอะไร

ระบบวัดความไม่สม่ำเสมอ 2 ด้าน แล้วใช้ค่าที่แย่กว่าเป็นตัวตัดสิน:

  • สูตรไม่คงที่ — อัตราการใช้ต่อหน่วยผลิตของแต่ละใบต่างกันมาก
  • ยอดรายเดือนแกว่ง — เดือนหนึ่งใช้น้อย อีกเดือนใช้มาก
แกว่ง ≤ 15%เชื่อมั่นสูง
แกว่ง ≤ 35%ปานกลาง
แกว่ง > 35% หรือมีข้อมูลไม่ถึง 3 เดือนผันผวน
ตัวอย่าง: ครีมวานิลลา พยากรณ์ 1,445 KG แต่ช่วงที่เป็นไปได้คือ 445–2,446 KG เพราะถูกใช้ในสินค้าตัวเดียว พอสัดส่วนการผลิตสินค้านั้นขยับ ความต้องการก็เหวี่ยงตามทันที
ต่างจากแป้งสาลีที่ใช้ในทุกสินค้า ความผันผวนของแต่ละตัวหักล้างกัน ตัวเลขจึงนิ่งกว่า
แนะนำให้กดปุ่ม "ผันผวน (ต้องระวัง)" ทุกครั้งก่อนสั่งซื้อ รายการที่ขึ้นมาคือกลุ่มที่ต้องดูช่วงที่เป็นไปได้ประกอบ หรือเช็คแผนการผลิตจริงก่อน

การ์ดตัวเลขด้านบนกดได้ — กดแล้วกรองตารางให้เหลือเฉพาะรายการนั้นทันที

10.4 ส่วนต่าง ๆ ในหน้านี้

ส่วนใช้ทำอะไร
ตารางวัตถุดิบปริมาณที่ต้องเตรียม พร้อมช่วงที่เป็นไปได้และกราฟย้อนหลัง
กำลังการผลิตชั่วโมงเครื่องจักรและแรงงานที่ต้องใช้ แปลงเป็นต่อวันทำงานและจำนวนกะ (กะละ 8 ชม.)
ความต้องการแยกตามคลังแต่ละคลังต้องรับของเท่าไหร่ ใช้วางแผนพื้นที่จัดเก็บ
สัดส่วนการผลิตสัดส่วนสินค้าที่จะผลิตและการเปลี่ยนแปลง — อธิบายว่าทำไมวัตถุดิบบางตัวถึงขยับ
แผนการผลิตรายผลิตภัณฑ์ยอดผลิตที่พยากรณ์ของแต่ละสินค้า

10.5 ความเชื่อมั่นและข้อจำกัด

เชื่อมั่นสูงใช้ตัวเลขวางแผนสั่งซื้อได้เลย
ปานกลางใช้ได้ แต่ควรดูช่วงที่เป็นไปได้ประกอบ
ผันผวนยังไม่ควรใช้ตัวเลขกลางสั่งของโดยตรง ควรตรวจสอบก่อน
ข้อจำกัด: ระบบยังไม่มีข้อมูลสต็อกคงเหลือ ตัวเลขที่แสดงคือ ปริมาณที่จะใช้ ไม่ใช่ ปริมาณที่ต้องสั่งซื้อ — ต้องหักของที่มีอยู่ในคลังออกเอง
ต้องมีข้อมูลย้อนหลังอย่างน้อย 3 เดือนที่จบแล้ว ระบบจึงจะพยากรณ์ได้ และเดือนปัจจุบันที่ยังไม่จบจะไม่ถูกนับ

11. สุขภาพการผลิต

หน้านี้ตอบคำถามคนละแบบกับหน้าพยากรณ์ — ไม่ได้บอกว่าต้องเตรียมของเท่าไหร่ แต่บอกว่ามีอะไรกำลังผิดปกติหรือไม่

11.1 ผลผลิตจริงเทียบแผน (Yield)

Yield = ยอดผลิตจริง ÷ ยอดผลิตตามแผน ของแต่ละเดือน

  • เทียบกับค่าเฉลี่ยของผลิตภัณฑ์ตัวเอง ไม่ได้เทียบข้ามสินค้า เพราะแต่ละสูตรมีอัตราสูญเสียปกติต่างกัน
  • สินค้าที่ Yield เดือนล่าสุดต่ำกว่าค่าเฉลี่ยตัวเองเกิน 2 จุด จะขึ้นสถานะ "ต้องตรวจสอบ"
  • มักหมายถึงปัญหาที่ไลน์ผลิตหรือคุณภาพวัตถุดิบ ควรตรวจก่อนกลายเป็นต้นทุนสะสม

11.2 ส่วนเกินจากแผน

เปรียบเทียบปริมาณที่เบิกจริงกับปริมาณตามแผน เพื่อหาว่าควรสั่งเผื่อเท่าไหร่

คอลัมน์ความหมาย
ควรสั่งเผื่อส่วนต่างที่เกิดเป็นประจำ เช่น +3% หมายถึงถ้าพยากรณ์ว่าใช้ 1,000 กก. ควรเตรียม 1,030 กก.
เกินมากที่สุดที่เคยเกิดกรณีแย่ที่สุดที่เคยบันทึกไว้ — ใช้ดูความเสี่ยง ไม่ควรใช้ตั้ง buffer ประจำ
เกินแผนบ่อยแค่ไหนเช่น 44 จาก 53 ครั้ง — ยิ่งบ่อยยิ่งแปลว่าเป็นรูปแบบที่เกิดซ้ำ ไม่ใช่ความบังเอิญ

ใช้ค่ามัธยฐาน ไม่ใช่ค่าเฉลี่ย เพราะการคีย์จำนวนผิดครั้งเดียวไม่ควรกลายเป็นยอดสั่งเผื่อถาวร

11.3 ปริมาณงานสแกนและต้นทุน AI

  • จำนวนใบเดือนล่าสุด พยากรณ์เดือนหน้า และค่าเฉลี่ยต่อวันที่มีงาน
  • กราฟปริมาณงานรายวัน 30 วันล่าสุด
  • ช่องกรอก ค่า AI ต่อการสแกน 1 ใบ → ระบบคำนวณต้นทุนที่คาดว่าจะเกิดเดือนหน้าให้

ระบบไม่เดาราคาต่อใบให้เอง เพราะแต่ละผู้ให้บริการและแต่ละรุ่นคิดไม่เท่ากัน ให้กรอกราคาจริงจากใบแจ้งหนี้ (ระบบจำค่าไว้ในเครื่องนี้)

11.4 รูปแบบการผลิตรายวันในสัปดาห์

ป้าย "หนักสุด" ตัดสินจากชั่วโมงแรงงานและเครื่องจักร ไม่ใช่จำนวนกิโลกรัม เพราะสินค้าแต่ละตัวใช้แรงงานต่อกิโลไม่เท่ากัน — วันที่ผลิตของง่ายจำนวนมาก อาจเบากว่าวันที่ผลิตของประกอบมือจำนวนน้อยกว่า
หากใบสั่งผลิตไม่มีบรรทัด Type = Resource เลย ระบบจะถอยไปจัดอันดับด้วยปริมาณ KG พร้อมแจ้งให้ทราบ

12. จัดการผู้ใช้งาน (Admin)

12.1 เพิ่มผู้ใช้ใหม่

  1. กดปุ่ม "เพิ่มผู้ใช้" มุมขวาบน เพื่อเปิดฟอร์ม
  2. กรอก อีเมล ของผู้ใช้ใหม่
  3. ตั้ง รหัสผ่าน เริ่มต้น — อย่างน้อย 6 ตัวขึ้นไป ไม่มีเงื่อนไขอื่น (ไม่บังคับตัวพิมพ์ใหญ่ ตัวเลข หรืออักขระพิเศษ)
  4. เลือก บทบาท — Staff / Reviewer / Approver / Admin
  5. กดปุ่ม "สร้างผู้ใช้"
ระบบทดสอบ Login ให้ทันทีหลังสร้าง ถ้าเข้าไม่ได้จะไม่ขึ้นว่าสำเร็จ — เมื่อสำเร็จจะแสดงข้อความยืนยันพร้อมอีเมลและรหัสผ่านที่ใช้ได้จริง ให้ตรวจทานอีกครั้งว่าอีเมลไม่พิมพ์ตก แล้วคัดลอกส่งให้ผู้ใช้ได้เลย
ช่องว่างหน้า-หลังจะถูกตัดออกให้อัตโนมัติ และอีเมลถูกแปลงเป็นตัวพิมพ์เล็ก เพื่อไม่ให้ช่องว่างที่ติดมาจากการคัดลอกทำให้เข้าระบบไม่ได้

12.2 รีเซ็ตรหัสผ่าน

กดปุ่ม 🔒 ท้ายแถวของผู้ใช้คนนั้น → ใส่รหัสผ่านใหม่ (อย่างน้อย 6 ตัวขึ้นไป) ระบบจะทดสอบ Login ให้เช่นกัน และปลดสถานะระงับบัญชีให้ด้วยหากเคยถูกระงับ

ใช้เมื่อผู้ใช้ลืมรหัสผ่าน — ผู้ดูแลตั้งรหัสใหม่ให้ได้โดยไม่ต้องสร้างบัญชีใหม่

12.3 แก้ไข Role

ในตารางผู้ใช้ กด Dropdown ข้าง Role เพื่อเปลี่ยนบทบาท → ระบบบันทึกทันที

12.4 กำหนดสังกัดโรงงาน

Super Admin สามารถกำหนดสังกัดโรงงานให้ผู้ใช้ได้โดยกด Dropdown ในคอลัมน์ "สังกัด"

ผู้ใช้ที่ยังไม่มีสังกัดโรงงานจะไม่สามารถอัปโหลดเอกสารได้ — ระบบจะแสดงข้อความ "ยังไม่ได้สังกัดโรงงาน กรุณาติดต่อ Admin เพื่อกำหนดโรงงาน"

12.5 Permission Matrix

ตาราง Checkbox แสดงสิทธิ์แต่ละ Role — Tick/Untick แล้วกด "บันทึกสิทธิ์"

ตารางครอบคลุมทุกหน้าในระบบ: แดชบอร์ด · สแกน · รายการ · ถามน้อง Order · พยากรณ์ · สุขภาพการผลิต · Export · ผู้ใช้งาน · ประวัติการใช้งาน · ตั้งค่า และสิทธิ์การดำเนินการ: อนุมัติ · ลบ

เมื่อระบบมีหน้าใหม่เพิ่มเข้ามา ทุกบทบาทจะได้รับสิทธิ์เริ่มต้นของหน้านั้นอัตโนมัติ เพื่อไม่ให้ใครเสียการเข้าถึงที่เคยมี จากนั้น Admin ปรับได้ตามต้องการ

Admin จะมีสิทธิ์ "ผู้ใช้งาน", "ตั้งค่า" และ "แดชบอร์ด" ติดตัวเสมอ ยกเลิกไม่ได้ เพื่อป้องกันการล็อกตัวเองออกจากระบบ

13. ตั้งค่าระบบ (Admin)

13.1 สแกนอัตโนมัติ

ระบบสแกนคิวอัตโนมัติ ทุก 5 นาที ตลอด 24 ชม. ไม่ต้องตั้งค่าใดๆ

13.2 โฟลเดอร์ Google Drive

  1. สร้างโฟลเดอร์ใน Google Drive
  2. แชร์โฟลเดอร์ให้ Service Account Email (คัดลอกได้จากหน้าตั้งค่า) ด้วยสิทธิ์ Editor
  3. วางลิงก์โฟลเดอร์ → กด "บันทึก"
  4. ระบบดึงไฟล์ใหม่เข้าคิวอัตโนมัติ แล้วย้ายไฟล์ที่ดึงแล้วไปโฟลเดอร์ย่อย "scanned"

ด้านบนสุดของหน้ามีแถบสรุปสถานะ 3 ช่อง — AI ที่ใช้อยู่ · สแกนอัตโนมัติ · Google Drive ดูได้ทันทีว่าอะไรพร้อมและอะไรยังไม่ได้ตั้งค่า

13.3 ตั้งค่า AI

เลือกผู้ให้บริการโดยกดที่การ์ด แต่ละการ์ดมีช่องใส่ API Key ของตัวเองและป้ายบอกว่ามีคีย์แล้วหรือยัง

Claude (Anthropic)แม่นยำสูง เหมาะกับลายมือภาษาไทย
Gemini (Google)ราคาประหยัด ประสิทธิภาพดี
GPT (OpenAI)ทางเลือกเพิ่มเติม

กรอก API Key ของแต่ละผู้ให้บริการ → กด "บันทึก" — คีย์เก็บฝั่งเซิร์ฟเวอร์ ไม่แสดงคีย์เต็ม

ผู้ให้บริการที่เลือกไว้จะถูกใช้ทั้งการสแกนเอกสารและการตอบคำถามของน้อง Order

13.4 ตัดภาพอัตโนมัติที่เส้นปะ

ตัวเลือกนี้ให้ระบบตัดภาพที่เส้นปะก่อนส่งให้ AI เพื่อลดค่าใช้จ่ายต่อใบ — ค่าเริ่มต้นคือปิด และแนะนำให้ปิดไว้

เหตุผลที่ปิดไว้: ถ้าตัดผิดตำแหน่ง คอลัมน์ทางขวาจะหายไปโดยไม่มีการแจ้งเตือน ข้อมูลที่ขาดหายแบบนี้ดูไม่ต่างจากข้อมูลที่ครบเลย ค่า AI ที่ประหยัดได้จึงไม่คุ้ม
หากเปิด ระบบจะตัดเฉพาะเมื่อพบเส้นปะที่ขอบขวาจริง ๆ และจะไม่ตัดถ้าต้องตัดเนื้อหาทิ้งเกิน 15% ของความกว้าง

13.5 ล้างข้อมูลเพื่อเริ่มระบบใหม่

อยู่ในแถบสีแดงล่างสุดของหน้าตั้งค่า กดที่แถบเพื่อเปิด (ปิดไว้เป็นค่าเริ่มต้น เพราะใช้นาน ๆ ครั้งและย้อนกลับไม่ได้) ใช้ตอนเปลี่ยนจากช่วงทดสอบไปใช้งานจริง

  1. เลือกขอบเขต — เฉพาะข้อมูลทดสอบ (ที่ระบบสร้างให้) หรือ ทั้งหมด
  2. เลือกว่าจะล้างประวัติการใช้งานด้วยหรือไม่
  3. ระบบแสดงจำนวนที่จะถูกลบให้ดูก่อน
  4. พิมพ์คำว่า ล้างข้อมูล ให้ตรง ปุ่มจึงจะกดได้
  5. กดปุ่ม แล้วยืนยันอีกครั้งในกล่องข้อความ
การลบไม่สามารถย้อนกลับได้ และไม่มีการสำรองข้อมูลอัตโนมัติ — หากต้องการเก็บข้อมูลเดิม ให้ Export เป็น Excel ก่อน
ผู้ใช้งาน สิทธิ์ และการตั้งค่าจะไม่ถูกลบ จึงไม่มีใครหลุดออกจากระบบ
การล้างข้อมูลจะถูกบันทึกไว้ในประวัติการใช้งานเสมอ ว่าใครทำเมื่อไหร่และลบไปเท่าไหร่

14. คำถามที่พบบ่อย (FAQ)

Q: สแกนแล้วชื่อผลิตภัณฑ์ผิด ทำอย่างไร?
A: กดแก้ไขรายการ แล้วแก้ช่อง "ผลิตภัณฑ์" ด้วยมือ → บันทึก Draft หรืออนุมัติได้เลย
Q: Qty (ตัวเลขเขียนด้วยมือ) อ่านผิด?
A: เปิดภาพต้นฉบับเทียบ แล้วแก้ไขค่า Qty ในตารางรายการ → Tick ยืนยันค่าต่าง
Q: สแกนล้มเหลว จะรู้สาเหตุได้อย่างไร?
A: ระบบแสดงเหตุผลเป็นภาษาไทยที่อ่านเข้าใจได้ในคิว เช่น ไฟล์เสียหาย ยังไม่ตั้ง API Key หรือเรียก AI ถี่เกินไป — ทำตามที่ข้อความแนะนำได้เลย
Q: อัปโหลดไฟล์ซ้ำจะเกิดอะไรขึ้น?
A: ระบบตรวจซ้ำด้วยเลข Production Order — หากซ้ำจะข้ามไฟล์นั้นอัตโนมัติ
Q: อนุมัติแล้วแก้ไขได้ไหม?
A: ไม่ได้ — รายการที่อนุมัติแล้วเป็นแบบอ่านอย่างเดียว เพื่อความถูกต้องของข้อมูล
Q: หารายการเก่าไม่เจอเพราะมีเยอะมาก?
A: ใช้ช่องค้นหาและตัวกรองช่วงวันที่ในหน้ารายการ หรือกดปุ่มลัด "เดือนที่แล้ว" / "30 วัน" ระบบจะโหลดรายการทั้งหมดให้ครบก่อนกรองเอง
Q: ตัวเลขที่น้อง Order ตอบ เชื่อถือได้แค่ไหน?
A: เชื่อถือได้เท่ากับข้อมูลในระบบ เพราะ AI ไม่ได้เป็นคนคำนวณ — มันแค่แปลคำถามเป็นเงื่อนไขค้นหาและเรียบเรียงคำตอบ ส่วนตัวเลขคำนวณโดยโปรแกรมจากฐานข้อมูลจริง กดดู "วิธีที่ระบบตีความคำถาม" ใต้คำตอบเพื่อตรวจสอบเงื่อนไขที่ใช้ค้นได้
Q: ถามเทียบ "เดือนนี้" แล้วตัวเลขดูลดลงเยอะผิดปกติ?
A: หากเดือนนี้ยังไม่จบ ระบบจะเทียบเป็นค่าเฉลี่ยต่อวันให้แทน พร้อมขึ้นกล่องเตือนสีเหลือง — ให้ดูตัวเลขต่อวันเป็นหลัก ไม่ใช่ยอดรวม
Q: หน้าพยากรณ์บอกว่ายังพยากรณ์ไม่ได้?
A: ต้องมีข้อมูลย้อนหลังอย่างน้อย 3 เดือนที่จบแล้ว เดือนปัจจุบันที่ยังไม่จบจะไม่ถูกนับ — สแกนเอกสารสะสมต่อไปอีกระยะแล้วลองใหม่
Q: ตัวเลขพยากรณ์เอาไปสั่งซื้อได้เลยไหม?
A: ยังไม่ได้ทั้งหมด — ตัวเลขคือ "ปริมาณที่จะใช้" ยังไม่ได้หักของที่มีในคลัง และควรบวกส่วนเกินจากแผน (ดูหน้าสุขภาพการผลิต) เข้าไปด้วย รายการที่ขึ้นว่า "ผันผวน" ควรตรวจสอบก่อนเสมอ
Q: จะรู้ได้อย่างไรว่าคีย์เข้า SAP ครบทุกใบแล้ว?
A: ดูแถบด้านบนหน้า Export — ถ้าขึ้นสีเขียวว่า "ส่งเข้า SAP ครบแล้วทุกใบ" แปลว่าไม่มีใบค้าง หากขึ้นสีเหลืองพร้อมจำนวน ให้กดปุ่ม "Export เฉพาะที่ยังไม่ได้ส่ง" เพื่อดึงเฉพาะใบที่ค้างออกมาในครั้งเดียว
Q: Export ไปแล้วแต่ไฟล์หาย ต้อง Export ใหม่ทำอย่างไร?
A: Export ซ้ำได้เลยตามปกติ โดยเลือกช่วงวันที่ที่ต้องการ — ระบบไม่บล็อกและสถานะจะไม่เปลี่ยน แต่ถ้าไฟล์นั้นยังไม่เคยถูกคีย์เข้า SAP เลย ให้ Admin กด "ยกเลิกการทำเครื่องหมาย" ที่ประวัติครั้งนั้นก่อน ใบเหล่านั้นจะกลับมาแสดงว่ายังไม่ได้ส่ง
Q: บนมือถือเข้าเมนู Export หรือ ตั้งค่า ไม่ได้?
A: แตะปุ่ม ☰ มุมบนซ้ายเพื่อเปิดเมนูทั้งหมด — แถบด้านล่างเป็นทางลัดเฉพาะเมนูที่ใช้บ่อยเท่านั้น
Q: อยากเริ่มระบบใหม่หมด ลบข้อมูลทดสอบทิ้ง?
A: Admin ไปที่ ตั้งค่า → โซนสีแดงล่างสุด เลือกขอบเขต ดูจำนวนที่จะถูกลบ แล้วพิมพ์คำยืนยัน — ผู้ใช้และการตั้งค่าจะไม่ถูกลบ แต่ควร Export Excel เก็บไว้ก่อน เพราะย้อนกลับไม่ได้
Q: ข้อมูลหลังเส้นปะจะถูกสแกนไหม?
A: ไม่ถูกบันทึก — ระบบอ่านเฉพาะคอลัมน์ "ลำดับ" ถึง "หน่วย" (ฝั่งซ้ายของเส้นปะ) แต่ตามค่าเริ่มต้นจะส่งภาพทั้งหน้าให้ AI อ่าน ไม่ตัดภาพ เพื่อไม่ให้คอลัมน์ขวาหายไปโดยไม่มีใครรู้
Q: Shelf Life ขึ้นสีส้มหรือติดลบ ต้องทำอย่างไร?
A: เปิดภาพต้นฉบับเทียบวันที่ MFG/EXP ของ batch นั้น แล้วแก้ให้ตรงกับเอกสาร — ถ้าติดลบแปลว่า EXP อยู่ก่อน MFG ซึ่งเป็นไปไม่ได้ มักเกิดจากสลับวัน/เดือน หากตรวจแล้วว่าถูกจริง กดยืนยันในกล่องที่ขึ้นมาเพื่อบันทึกต่อได้
Q: ลบ batch หรือแก้ MFG/EXP แล้วบันทึก ทำไมยังเห็นข้อมูลเดิมใน Excel?
A: ไม่เกิดขึ้นแล้ว — เดิมข้อมูล batch ถูกตัดทิ้งระหว่างทางก่อนถึงฐานข้อมูล ตอนนี้แก้แล้ว การเพิ่ม/ลบ/แก้ batch จะถูกบันทึกครบทุกครั้ง หากยังเห็นของเก่า ให้กด Export ใหม่อีกครั้ง
Q: สร้างผู้ใช้แล้วเข้าระบบไม่ได้?
A: ตรวจข้อความยืนยันตอนสร้าง — ระบบจะแสดงอีเมลและรหัสผ่านที่ทดสอบ Login ผ่านแล้ว สาเหตุที่พบบ่อยที่สุดคือพิมพ์อีเมลผิดตอนสร้าง (คนละอีเมลกับที่ใช้ Login) ให้เทียบตัวสะกดในตารางผู้ใช้ หากลืมรหัสผ่านให้กดปุ่ม 🔒 เพื่อตั้งใหม่
Q: อัปโหลดหลายไฟล์แล้วขึ้นว่าไม่สำเร็จ ทั้งที่ไฟล์เข้าคิวครบ?
A: แก้แล้ว — เดิมการอัปโหลดหลายไฟล์พร้อมกันใช้เวลานานจนหมดเวลารอ ทำให้ขึ้นว่าล้มเหลวทั้งที่เข้าคิวได้จริง ตอนนี้อัปโหลดทีละไฟล์พร้อมตัวนับความคืบหน้า และสรุปจำนวนที่สำเร็จจริงเมื่อจบ
Q: สถานะ "ต้องตรวจสอบ" คืออะไร เกิดจากอะไร?
A: ระบบจะ flag "ต้องตรวจสอบ" เมื่อ AI อ่านข้อมูลได้ไม่ครบหรือพบความขัดแย้ง เช่น ไม่พบยอด Plan, ไม่พบหน่วย, หรือวันหมดอายุมาก่อนวันผลิต — ไม่ได้หมายความว่าข้อมูลผิดเสมอ แต่ควรตรวจสอบกับเอกสารต้นฉบับก่อนอนุมัติ (ดูข้อ 7.1)
Q: ปิดเครื่อง / ปิด browser แล้วเอกสารในคิวจะถูกสแกนไหม?
A: ได้ — ระบบสแกนอัตโนมัติทุก 5 นาทีบน Cloud ไม่ต้องเปิดเครื่องทิ้งไว้ เอกสารที่อยู่ในคิวจะถูกสแกนภายไม่เกิน 5 นาที เปิด browser กลับมาเมื่อไหร่ก็เห็นผลสแกนเรียบร้อย
Q: อัปโหลดไม่ได้ ขึ้นว่า "ยังไม่ได้สังกัดโรงงาน"?
A: ติดต่อ Super Admin ให้กำหนดสังกัดโรงงานให้ที่หน้า "ผู้ใช้งาน" — เมื่อมีสังกัดแล้วจะอัปโหลดได้ทันที
